# ClipPal v2.0.0 架构设计

## 1. 设计目标

ClipPal 2.0.0 采用单机版、自建版、商业版三层递进架构。三种版本共享同一套本地核心能力，并通过代码依赖逐层扩展：

```text
单机版 -> 自建版 -> 商业版
```

依赖方向只能从左向右，不能让开源核心反向依赖商业代码。

## 2. 两个代码仓库

### 2.1 开源仓库：clip-pal-selfhost

开源仓库提供单机版和自建版的全部能力，并向商业仓库发布稳定的核心包。

```text
clip-pal-selfhost/
├── crates/
│   ├── clip-core/              # 本地剪贴板核心
│   ├── clip-sync-protocol/     # 客户端和服务端共用协议
│   ├── clip-sync-client/       # HTTP、SSE、同步队列和附件同步
│   ├── desktop-app-core/       # 单机版桌面应用组装核心
│   └── selfhost-app-core/      # 自建版核心，依赖单机版并接入同步
├── apps/
│   ├── desktop/                # 单机版/自建版 Tauri 应用
│   └── sync-server/            # 开源自建同步服务端
├── packages/
│   └── ui-core/                # 基础前端页面和公共组件
├── migrations/
├── protocol/
└── scripts/
```

单机版只使用 `clip-core`、`desktop-app-core` 和基础前端；自建版在此基础上启用同步客户端并连接用户自己的 `sync-server`。

### 2.2 商业仓库：clip-pal-commercial

商业仓库依赖开源仓库发布的核心包，在其上增加商业功能和公共云服务。

```text
clip-pal-commercial/
├── crates/
│   ├── commercial-client/      # 账号、VIP、支付和商业 API
│   ├── commercial-server/      # 公共商业云服务扩展
│   └── commercial-policy/      # 配额和商业权限策略
├── apps/
│   ├── desktop-commercial/     # 商业版桌面应用
│   ├── cloud-server/           # 公共商业云服务
│   └── admin-console/          # 管理后台
└── packages/
    └── ui-commercial/          # 商业前端页面
```

商业仓库只直接依赖 `selfhost-app-core`。`selfhost-app-core` 再依赖单机版核心、同步协议和同步客户端，商业版通过配置和扩展接口覆盖自建版默认实现。

## 3. 三种版本

```text
单机版 = 本地剪贴板核心 + 基础桌面应用 + 基础前端

自建版 = 单机版 + 开源同步客户端 + 开源自建服务端

商业版 = 自建版核心 + 账号/VIP/支付/配额 + 公共商业云服务
```

- 单机版不编译同步运行时代码，也不访问同步服务。
- 自建版不要求用户账号，使用部署地址、部署令牌和部署级同步配置。
- 商业版复用自建版的同步核心，只增加商业认证、权益和服务限制。

## 4. 同步设计

- SSE 用于在线状态下的实时变更通知。
- HTTP 用于提交本地变更，以及登录、启动或网络恢复后的查缺补漏。
- 服务端保存有序变更日志和游标，SSE 断线后可以通过 HTTP 继续拉取。
- 客户端使用持久化 Outbox、游标和附件任务，保证重启、断网和重复事件下能够恢复。
- 自建服务端可以读取该部署中的同步数据。
- 所有通信使用 HTTPS；部署认证令牌与同步数据密钥分开管理。

## 5. 扩展规则

### 本地核心

只负责剪贴板监听、SQLite、搜索、窗口、快捷键、自动粘贴和本地设置，不依赖同步、VIP 或商业服务。

### 同步核心

负责同步协议、HTTP/SSE、Outbox、游标、重试、冲突处理和附件传输，不依赖商业账号或支付系统。

### 商业扩展

通过认证、配额、权益和服务地址等扩展接口接入公共商业云，不修改开源核心的基本职责。

### AI 扩展

AI 作为可选扩展能力接入。自建版可以配置自建或 OpenAI 兼容服务，商业版可以提供商业 AI 服务和额度限制。AI 只能通过受控的上下文服务读取剪贴板内容，前端负责展示，Rust 后端负责数据选择、调用和权限控制。

## 6. 构建原则

使用 Rust Cargo feature 和前端构建模式生成不同版本：

```text
local       = 单机版
self-hosted = 自建版
commercial  = 商业版
```

商业仓库固定依赖开源仓库发布的 `selfhost-app-core` Git tag 或版本号，不直接依赖开发分支；自建版核心内部再依赖单机版核心。开源仓库的公共包必须保持稳定 API 和明确的协议版本。
