# ClipPal v2.0.0 架构设计

## 1. 设计目标

ClipPal 2.0.0 采用单机版、自建版、商业版三层递进架构。三种版本共享同一套本地核心能力，并通过代码依赖逐层扩展：

```text
单机版 -> 自建版 -> 商业版
```

以上箭头表示功能逐层扩展；实际代码依赖为“商业版依赖自建版，自建版依赖单机版”，开源核心不能反向依赖商业代码。

## 2. 两个代码仓库

### 2.1 开源仓库：clip-pal-selfhost

开源仓库提供单机版和自建版的全部能力，并向商业仓库发布稳定的核心包。

```text
clip-pal-selfhost/
├── crates/
│   ├── clip-core/              # 本地剪贴板核心
│   ├── clip-sync-protocol/     # 客户端和服务端共用协议
│   ├── clip-sync-client/       # HTTP、SSE、同步队列和附件同步
│   ├── desktop-app-core/       # 单机版桌面应用组装核心
│   └── selfhost-app-core/      # 自建版核心，依赖单机版并接入同步
├── apps/
│   ├── desktop/                # 单机版/自建版 Tauri 应用
│   └── sync-server/            # 开源自建同步服务端
├── packages/
│   └── ui-core/                # 基础前端页面和公共组件
├── migrations/
├── protocol/
└── scripts/
```

单机版只使用 `clip-core`、`desktop-app-core` 和基础前端；自建版在此基础上启用同步客户端并连接用户自己的 `sync-server`。

### 2.2 商业仓库：clip-pal-commercial

商业仓库依赖开源仓库发布的核心包，在其上增加商业功能和公共云服务。

```text
clip-pal-commercial/
├── crates/
│   ├── commercial-client/      # 账号、VIP、支付和商业 API
│   ├── commercial-server/      # 公共商业云服务扩展
│   └── commercial-policy/      # 配额和商业权限策略
├── apps/
│   ├── desktop-commercial/     # 商业版桌面应用
│   ├── cloud-server/           # 公共商业云服务
│   └── admin-console/          # 管理后台
└── packages/
    └── ui-commercial/          # 商业前端页面
```

商业仓库只直接依赖 `selfhost-app-core`。`selfhost-app-core` 再依赖单机版核心、同步协议和同步客户端，商业版通过配置和扩展接口覆盖自建版默认实现。

## 3. 三种版本

```text
单机版 = 本地剪贴板核心 + 基础桌面应用 + 基础前端

自建版 = 单机版 + 开源同步客户端 + 开源自建服务端

商业版 = 自建版核心 + 账号/VIP/支付/配额 + 公共商业云服务
```

- 单机版不编译同步运行时代码，也不访问同步服务。
- 自建版不要求用户账号，使用部署地址、部署令牌和部署级同步配置。
- 商业版复用自建版的同步核心，只增加商业认证、权益和服务限制。

## 4. 同步设计

- SSE 用于在线状态下的实时变更通知。
- HTTP 用于提交本地变更，以及登录、启动或网络恢复后的查缺补漏。
- 服务端保存有序变更日志和游标，SSE 断线后可以通过 HTTP 继续拉取。
- 客户端使用持久化 Outbox、游标和附件任务，保证重启、断网和重复事件下能够恢复。
- 自建服务端可以读取该部署中的同步数据。
- 所有通信使用 HTTPS；部署认证令牌与同步数据密钥分开管理。

## 5. 扩展规则

### 本地核心

只负责剪贴板监听、SQLite、搜索、窗口、快捷键、自动粘贴和本地设置，不依赖同步、VIP 或商业服务。

### 同步核心

负责同步协议、HTTP/SSE、Outbox、游标、重试、冲突处理和附件传输，不依赖商业账号或支付系统。

### 商业扩展

通过认证、配额、权益和服务地址等扩展接口接入公共商业云，不修改开源核心的基本职责。

### AI 扩展

AI 作为可选扩展能力接入。自建版可以配置自建或 OpenAI 兼容服务，商业版可以提供商业 AI 服务和额度限制。AI 只能通过受控的上下文服务读取剪贴板内容，前端负责展示，Rust 后端负责数据选择、调用和权限控制。

## 6. 构建原则

使用 Rust Cargo feature 和前端构建模式生成不同版本：

```text
local       = 单机版
self-hosted = 自建版
commercial  = 商业版
```

商业仓库固定依赖开源仓库发布的 `selfhost-app-core` Git tag 或版本号，不直接依赖开发分支；自建版核心内部再依赖单机版核心。开源仓库的公共包必须保持稳定 API 和明确的协议版本。

## 7. 当前已落地的目录与依赖

当前分支：`v2.0.0`。公共包使用 `2.0.0-alpha.1`，桌面应用仍保留原发布版本号；
本次属于结构迁移，不代表发布 v2.0.0 正式版。

```text
crates/
├── clip-core/             # 记录/设置模型、统一错误、仓储接口、SQLite、内存搜索
├── clip-sync-protocol/    # 当前线上 JSON 契约及模型转换
├── clip-sync-client/      # HTTPS、SSE、上传与补拉任务、传输和存储端口
├── desktop-app-core/      # 单机业务：采集、查询、缓存清理、内容转换和 LocalContext
└── selfhost-app-core/     # SelfhostContext：持有完整 LocalContext 和同步资源
crates/desktop-tauri/src/   # 独立的 Tauri 桌面适配包
├── app_context.rs         # 桌面运行资源、窗口/自动粘贴状态与版本资源入口
├── core/application/      # IPC 用例、系统剪贴板、设置、更新和可选同步副作用
├── desktop/               # 系统能力、shell 窗口/托盘/快捷键、路径和密钥适配
├── bootstrap/             # 核心初始化、插件和生命周期组装
├── commands/              # 固定响应信封的 IPC 边界
├── sync/                  # 可选同步任务与 HTTP 认证适配
├── commercial/            # 可选账号/VIP领域、网关、存储和商业策略
├── network/               # 同步与商业 HTTP/重试适配
└── lib.rs                 # run(context, PackagedAssets)
src-tauri/
├── src/main.rs            # 进程和异步运行时入口
├── src/lib.rs             # 生成 context、嵌入打包配置/图标并调用适配包
├── Cargo.toml / build.rs  # 版本 feature 转发与 Tauri 构建
├── tauri*.conf.json       # 宿主打包与平台配置
├── capabilities/          # Tauri 权限
└── icons/                 # 安装包及托盘图标
frontend/                  # 原有 Vue 页面及交互，未物理搬动
```

实际代码依赖（箭头表示“依赖”）：

```text
src-tauri 启动壳 ──→ desktop-tauri（可选商业组装）──→ selfhost-app-core ──→ desktop-app-core ──→ clip-core
                             └──→ clip-sync-client ──→ clip-sync-protocol
```

单机 profile 直接使用 `desktop-app-core`；同步 profile 使用 `selfhost-app-core`。
`AppContext` 作为桌面统一入口委托给对应应用核心，同时持有 Tauri 运行资源和商业扩展资源。
`clip-core` 和两个应用核心不引用 `src-tauri`。协议包独立定义同步数据结构，客户端只负责网络传输和会话调度。

### 已保持的兼容性

- SQLite 表名、字段名和原有排序、同步状态数值保持不变，不要求删除用户数据。
- 数据目录和设置文件路径仍由桌面层解析，再注入公共核心。
- 搜索初始化使用注入的解密函数，密钥来源和现有密文格式仍由应用层管理。
- `ClipRecord` 不再实现数据库方法；插入、同步合并事务归属 SQLite 仓储。
- 自建同步 DTO 使用 snake_case，跨端使用 `content_key` 标识内容。
- 原有业务接口兼容保留，新增版本能力接口；前端根据能力控制入口和记录上限，CSS 未修改。

### 尚未完成的部分

1. 当前 `desktop-tauri/src/commercial/` 仍在同一仓库；领域模型、网关、安全存储和 HTTP 认证适配已集中到该目录，
   尚未发布独立商业扩展包，也没有创建或发布远程商业仓库。
2. 自建客户端已接入部署令牌与独立策略，尚无真实自建服务端完成端到端联调，
   不代表已交付完整自建同步系统。
3. `local` 已排除共享同步客户端依赖及同步任务；非商业构建不注册账号/VIP/支付 IPC，
   页面不展示对应入口且不初始化商业会话或权益。单机不编译商业模块、HTTP 插件和远程任务，
   但软件更新仍使用原有流程，不能把它描述为所有联网能力已移除的最终单机安装包。
4. 自建文本同步使用持久化待传队列和 HTTPS 游标补拉，SSE 通知负责唤醒补拉。
   开源服务端、附件同步及恢复换代的数据集仍待实现。
5. `apps/desktop`、`apps/sync-server`、`packages/ui-core` 的最终布局仍为规划。
   暂时保留 Tauri 和 Vite 路径，避免影响现有打包入口；两个仓库的分离在公共依赖稳定后进行。

## 9. 部署认证与版本策略（当前阶段）

- `ApplicationPolicy` 是桌面策略端口，由 `bootstrap` 注入；本地监听、设置与同步任务
  不再直接引用 `VipService`、商业模块或账号令牌管理器。
- 商业策略保留原有 VIP 校验、刷新、同步文件大小和复制限制；商业凭据 provider 保留
  访问令牌/刷新令牌逻辑。
- 单机/自建的本地记录条数不受商业套餐限制（仅保留现有 SQL `i32` 上限），
  本地文件复制不再查询商业套餐；自建同步附件大小仍由部署配置控制。
- 自建 provider 使用固定部署令牌，采用 `Authorization: Bearer <deployment_token>`。
  地址要求 HTTPS，可配置反向代理路径前缀；认证地址不得含 URL 用户名、查询参数或片段。
- 自建令牌遇到 401 直接报告同步认证失败，不刷新商业令牌、不登出账号、也不删除部署配置。
  商业 provider 遇到 HTTP 或业务信封 401 时最多刷新重试一次；网络失败不触发刷新。
- 未配置自建令牌或配置无效时，同步认证保持禁用，本地功能仍可使用，开启同步会返回配置提示。
- `get_app_capabilities` 仅返回版本、同步/账号入口能力与记录上限，不返回地址、密钥或部署令牌。

配置样例：`src-tauri/config.selfhost.example.json`。按样例给本地被忽略的 `src-tauri/config.json`
补充 `cloud_sync.deployment_token` 并在确认同步已有文本后设定 `cloud_sync.enabled: true`。
保留原有数据加密密钥。同一部署的客户端使用同一部署令牌和数据加密密钥。
样例中的密钥和令牌是占位符，不能直接作为可用配置。现有商业配置没有此字段仍兼容。
不要为了切换版本直接覆盖已有数据密钥，本次也未修改用户的 `config.json` 或正式数据文件。

自建客户端已接入持久化待传队列、SSE、游标补拉和文本回放。服务端需实现部署令牌校验及
[云同步设计](cloud-sync-design.md)中的 V2 接口。真实服务端联调仍待完成。

## 10. 单机版迁移进度（2026-11-21）

当前优先完成单机版；同步、服务端、商业拆仓与 AI 扩展暂停。默认 feature 已从商业版切换为
`local`。构建自建版或商业版时显式使用 `--no-default-features --features self-hosted/commercial`。

### 业务归属

- `desktop-app-core/capture.rs`：文本加密入库、图片保存、文件缓存、去重排序、索引更新。
  设备身份、编码器、资源路径和扩展限制通过参数注入，不读取全局 `AppContext` 或商业服务。
- `desktop-app-core/records.rs`：分页搜索、预览/全文、文件信息、图片路径、置顶、删除。
- `desktop-app-core/cleanup.rs`：条数保留、墓碑清理、应用资源回收。
- `desktop-app-core/content.rs`、`dto.rs`、`settings.rs`、`temporary_files.rs`、`update.rs`：
  公共内容处理、交互契约、设置校验、保留文件名称的临时副本和更新契约。
- `clip-core/crypto.rs`、`files/`：参数化 AES-256-GCM 与通用文件工具。
- `desktop-tauri/src/desktop/`：系统剪贴板/粘贴、托盘/菜单/窗口/快捷键、配置密钥读取和日志。
  Tauri 的实际操作仍归桌面适配层；前端样式和业务交互入口保持原样。

### 删除与数据兼容

旧 `biz`、`services`、`infra`、`domain`、`dto`、`utils`、`api`、`system`、
`sqlite_storage.rs` 以及散落的桌面系统入口已迁移并删除，不保留旧目录转发。
已有同步实现集中保留在 `sync/`，只做迁移适配，未新增同步能力。

单机删除直接物理删除记录、移除索引并回收受管资源；自建/商业构建仍保留同步墓碑语义。
启动时清理超限记录及可清理墓碑后再初始化索引。缓存删除规范化路径并验证资源目录边界，
不删除外部源文件、多文件原件或指向资源目录外的符号链接目标。
采集、删除与清理共享实例级互斥锁，避免同一记录入库和清理并发交错。

保持原 SQLite 字段、数据目录、设置文件、密钥来源及 `Base64(nonce + ciphertext + tag)` 格式；
不修改正式数据和本地 `config.json`。测试覆盖旧密文向量、旧数据库读写、加密采集、中文搜索、
UTF-8 预览、去重排序、图片/文件缓存、置顶保留、无云端墓碑清理和非法参数。
图片另存为等待系统对话框与实际写入完成，取消不报告保存成功，文件错误写入日志并返回通用提示。


### 无用代码收尾清理

删除旧架构遗留的空 `application/`、`infrastructure/`、`interfaces/`、`platform/`、`shared/` 目录。
账号、权益、协议、游标和队列的纯转发模块已移除，调用方直接使用实际实现或公共 crate。
AI 方案保留在设计文档中，当前未接入的 AI 占位源码已删除，后续实现时再引入具体模块。
同时移除无调用方的 HTTP 原始响应/表单/通用上传封装、旧存储辅助方法、重复响应构造器、
未使用的上下文访问器及依赖声明；仍在使用的同步与商业实现保留。
前端模板图标、无用的托盘资源和对应打包声明已移除，不改变页面样式和交互。
认证存储的序列化字段及顺序保持不变，避免破坏已有 bincode 文件。

单机版后续稳定性修复与验证边界见 [单机版验证记录](standalone-validation.md)。

## 11. 薄启动壳已落地

`src-tauri/src` 仅剩 `main.rs` / `lib.rs`，原有 75 个桌面实现文件迁入
`crates/desktop-tauri/src`，不保留旧路径兼容转发或空目录。

`desktop-tauri::run(context, PackagedAssets)` 负责实际初始化、插件注册、IPC 注册和运行事件。
`tauri::generate_context!()` 仍由应用壳调用，确保应用版本、应用标识、capabilities、
前端资源及平台配置始终属于最终打包宿主。

配置 JSON 和托盘图标由应用壳通过 `include_str!` / `include_bytes!` 嵌入，再显式注入
适配包；适配包不能读宿主的路径或配置文件，不携带另一份打包密钥。
现有配置内容、密钥混淆、加解密算法、数据路径及前端样式不因本次迁移改变。
配置初始化在创建数据库及搜索索引之前完成，重复初始化返回错误。

启动壳的 `local/self-hosted/commercial/sync/commercial-extension` feature 一对一转发到
适配包，并关闭适配包的默认 feature，以便显式选择自建或商业构建。
单机仍只构建本地实现，可选同步/商业实现迁移后继续通过 feature 隔离，功能暂不扩展。
纯业务 crate 保持不依赖 Tauri；`desktop-tauri` 作为框架适配层可以依赖 Tauri，不能反向依赖 ClipPal。

Tauri 的构建脚本仅从直接依赖读取插件权限元数据。因此启动壳 `Cargo.toml` 中保留与
capabilities 对应的 opener/dialog/autostart/global-shortcut/window-state 插件依赖；
这是框架打包声明，注册和调用仍归适配包。`serde_json` 保留用于 `generate_context!` 宏展开。
不能为了减少依赖声明而删除现有权限或放宽 capability。

桌面服务与策略测试改在 `cargo test -p desktop-tauri --lib` 及对应 profile 下执行。
`cargo test -p ClipPal --lib` 只验证薄壳，不再包含原桌面测试。
结构检查脚本验证 src-tauri 源码只剩两个入口文件、feature 正确转发、壳中无业务依赖，
以及适配包不通过相对路径读取宿主资产。

迁移新增了 Tauri 官方 mock runtime 的 IPC 验证：通过真实注册表调用本地记录查询、错误参数和版本能力接口，并确认单机不注册登录命令；另验证宿主资产注入的初始化顺序、失败不残留部分状态及重复初始化保护。测试不访问正式记录和系统剪贴板。

本轮验证结果：`cargo check --workspace`、自建/商业壳编译检查、

## 当前单机数据库拆分（覆盖前文的旧字段兼容状态）

当前单机核心已改为自增 id + content_key 唯一索引的 clip_record，以及通过 record_id
关联的 clip_record_resource。同步模型、仓储操作和设置已从单机核心删除。首版开发阶段按
当前结构初始化新库。字段和业务闭环详见 [单机数据库 v2](local-database-v2.md)。

自建版首版采用持久化增删动作、按序补传和游标回放，表职责及验收场景见 [云同步设计](cloud-sync-design.md)。
依赖关系仍为商业 → 自建 → 单机，不增加第三个仓库；开源仓库提供单机和自建，商业
仓库以后通过稳定包依赖自建核心，前文目录规划不是已经发布这些独立依赖包的声明。
